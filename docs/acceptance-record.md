# 手動受け入れ記録用紙

[運用設計](operations.md) 8 章の 19 項目を、ホームラボで実施したときに記録するための用紙である。手順の背景と根拠は [要件定義](requirements.md) 9 章と各設計書を参照する。自動テストで担保できる範囲は [運用設計](operations.md) 7.1 の分類表にある。

## 記録のしかた

- 1 回のリリース（または構成変更）につき 1 枚を使う。実施日・実施者・対象リビジョンを先に埋める。
- 「結果」は `OK` / `NG` / `N/A` のいずれかで書く。`NG` は必ず「事象」と「切り分け」を残す。
- 証跡（`journalctl` の抜粋、`systemctl show` の出力、画面のスクリーンショット）は「証跡」欄にファイル名か貼り付け先を書く。
- 環境固有の値（ホスト名・IP・ポート・URL）は記入例のままだと本番と食い違うため、実施環境の値に置き換えて記録する。

## 事前準備（1〜5）

| #   | 手順                                                                                 | 確認すること                                                                     | 結果 | 証跡 / 備考 |
| --- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- | ---- | ----------- |
| 1   | 専用の SSH 鍵を作成し、各対象へ公開鍵を配備する                                      | 鍵が `POWER_MANAGER_SSH_IDENTITY_FILE` のパスにあり、所有権と権限が 600 である   |      |             |
| 2   | 各対象の `sudoers` に停止コマンドのみをパスワードなしで許可する                      | 許可範囲が `operations.md` 2 章の停止コマンドに限られ、他は拒否される            |      |             |
| 3   | 各対象のホスト鍵を `known_hosts` に登録する                                          | `known_hosts` に全対象のエントリがあり、`ssh -o BatchMode=yes` で接続できる      |      |             |
| 4   | 管理対象 JSON と環境変数ファイルを作成し `/home` の外に配置する                      | 両方とも `/etc` 配下にあり、サービス専用ユーザーから読める                       |      |             |
| 5   | NixOS サービスを起動し active を確認する                                             | `systemctl status power-manager` が active、`journalctl` に `started` が 1 行出る |      |             |
