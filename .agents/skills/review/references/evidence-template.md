# evidence.md の書式

`collect-evidence.sh` が骨組みを作り、オーケストレータが `## 1` と `## 3` を埋める。
レビュアーはこの 1 ファイルから出発し、探索をしない。

```markdown
# {{TICKET}} レビュー対象 evidence

生成: {{日時}}
base: {{base-ref}}    head: {{head-ref}}
作業ディレクトリ: {{PWD}}

## 1. チケット / 受け入れ条件

{{受け入れ条件を箇条書き。要件定義の該当行を file:line 付きで引用}}

## 2. 差分

{{shortstat と対象ファイル一覧}}

### diff

```diff
{{git diff base...head の全文}}
```

### 変更ファイル全文

#### app/foo.ts

```ts
{{全文。差分だけでは文脈が足りない}}
```

## 3. 検証済み事実

レビュアーはここを再検証しない。**すべて file:line か実行ログの該当行付き。**

### 3.1 実行して確認したこと

```text
$ npm run check
{{結果。エラーがあれば全文}}

$ npm run smoke
{{同上}}
```

- {{実行結果から読み取れる事実}}
  例: smoke は `app/routes/status.ts:88` の分岐を通らないため、異常系の挙動は未検証

### 3.2 フレームワーク・依存の挙動（判断が割れる点）

- {{ライブラリ}} の {{関数}} は {{挙動}}。根拠: `node_modules/{{pkg}}/{{file}}:{{line}}`
  例: react-router 8 の `redirect` は `Response` を throw するので catch で握ると 500 になる

### 3.3 仕様の該当箇所

- `docs/requirements.md:{{行}}-{{行}}`: {{該当要件の引用}}
- `docs/architecture.md:{{行}}-{{行}}`: {{該当設計の引用}}

### 3.4 対象外・既知の未対応

- {{項目}} は今回のスコープ外（理由: {{理由}}）
- {{項目}} は既存の未対応で、このチケットでは扱わない

## 4. レビュー時の注意

- 上記に無い情報が必要な場合は、レポート末尾の「未確認事項」に 1 行で書くだけにする。
- ここに書かれた事実を疑う場合も、実験のやり直しはしない。
```

## 何を書くか

| 書く | 書かない |
|---|---|
| 実際にコマンドを走らせた結果 | コードを読んで推測した内容 |
| 判断が割れる依存挙動（file:line 付き） | 一般常識、言語仕様の説明 |
| 仕様書の該当行の引用 | 要件定義の全体要約 |
| 「これは対象外」という明示 | レビュアーに判断させる余地 |

file:line が無い事実は、レビュアーにとって「未確認」と同じである。
その瞬間に「念のため確認」が始まり、探索モードに落ちる。

## findings.md（統合結果）

レビュアーの出力はそのまま改修者に渡さない。次の形に自分でまとめる。

```markdown
# {{TICKET}} レビュー統合

## 採用（改修する）
- [ ] MUST: `app/foo.ts:42` …（出典: code / security）
- [ ] NITS: `test/bar.test.ts:18` …

## 却下（理由付き）
- IMO: … — 品質差が小さいため見送り
- MUST: … — 根拠の file:line を確認したが該当箇所に問題なし（誤検知）

## 未確認事項
- …
```
